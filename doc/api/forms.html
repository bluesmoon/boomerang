The Forms Plugin

The forms Plugin tracks all form submissions on a page and beacons them to a dedicated endpoint on your beacon-server.

The forms API is encapsulated in the BOOMR.plugins.forms namespace

WARNING: Be aware that this plugin uses the HTTP POST-Method to send data to the beacon-server as it can not anticipate the size of the to be sent data entirely

Configuration

The forms plugin configuration is contained in the forms namespace in the initial Boomerang configuration Object.

See "Howto #6 — Configuring boomerang" for more information on how to configure Boomerang

forms_url
[required] The Url the form submission events are supposed to be sent to. You need to specify this.

Methods

init(oConfig)

Called by the BOOMR.init() method to configure the forms plugin. 

      BOOMR.init({
        forms: {
          forms_url: "http://<your beacon server>/forms"
        }
      });

Parameters

oConfig
The configuration object passed in via BOOMR.init(). See the Configuration section for details.

Returns

a reference to the BOOMR.plugins.forms object, so you can chain methods.

Beacon Parameters

The following parameters are sent when a forms event is triggered.

form_data
An array of JSON.stringified values from the submitted form

The following parameters are contained in the Object which is part of the submitted form_data Array

name
The name attribute of the submitted input form element
value
The value of the submitted input form element
type
The type of element to be submit
id
The id of the element

For a simple input form the returned values may look like this:

    "form_data": [
        {
            "name": "name",
            "value": "Andreas Marschke",
            "type": "text",
            "id": "text"
        },
        {
            "name": "email",
            "value": "andreas.marschke@gmail.com",
            "type": "email",
            "id": "email"
        },
        {
            "name": "comment",
            "value": "Thank you for this dishwashing ninja!",
            "type": "textarea",
            "id": "textarea"
        }
    ]

Implementation Details for Webmasters/Developers

Please be aware that there are options provided by the plugin to also prevent you from accidentally beaconing back the password or other personal details of your users. It does not automatically filter out all personal information in your forms. As the webmaster however you may add HTML-Attributes to your sensitive input elements and form elements to prevent them from being sent back

Specifically this plugin looks for attributes data-sensitive and data-boomerang-sensitive in your form elements should you have tagged sensitive elements this way properly they will be filtered out by the plugin.

An example implementation in your markup may look like this:

<form method="post" action="/login" data-sensitive="true">
  <!-- Your Login Form elements here -->
</form>

Above code would exclude the complete form from being beaconed back to your beacon-server

On the other hand you may have forms that contain some elements that you would prefer stayed between your customer and the form submi and would not be send as a beacon. But the form also has data you'd still like to have. An example would be the a comment section:

    <form method="post" action="/post/20/comment">
      <input type="text" class="form-control" name="name" value="" placeholder=""  data-sensitive="true"/>
      <input type="email" class="form-control" name="email" value="" placeholder="" data-sensitive="true"/>
      <select name="rating">
	<option>1</option>
	<option>2</option>
	<option>3</option>
	<option>4</option>
	<option>5</option>
      </select>
      <textarea name="comment" id="comment" rows="30" cols="60" data-sensitive="true"></textarea>
    </form>

In this example we would only beacon back the rating without any further data on the person sending this rating or their textual commentary since these are things your blogging engine may be better at handling than your beacon-server.
